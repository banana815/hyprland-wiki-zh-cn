# 基础配置

> [!WARNING]
> 默认配置仅涵盖 Hyprland 的部分选项和功能。要了解所有配置选项，请参阅本 Wiki 这一节链接到的各个页面。

配置文件位于 `$XDG_CONFIG_HOME/hypr/hyprland.lua`。在大多数情况下，该路径对应 `~/.config/hypr/hyprland.lua`。

启动 Hyprland（`start-hyprland`）时可以传入参数，但必须将参数放在 `--` 之后。例如，要通过 `--config`（或 `-c`）让 Hyprland 加载非默认配置，可以运行 `start-hyprland -- --config ~/myRices/medium_rare/hyprland.lua`。

如果尚无配置文件，Hyprland 会创建一份[示例配置](https://github.com/hyprwm/Hyprland/blob/main/example/hyprland.lua)。删除 `hl.config({ autogenerated = true })` 即可移除提示配置由系统自动生成的警告横幅。

检测到文件变更时，Hyprland 会重新加载配置。要手动重新加载，请使用 `hyprctl reload`。

要查看窗口信息（类名、大小、标签等），可使用以下命令：
- `hyprctl clients` 显示所有窗口的信息
- `hyprctl activewindow` 仅显示活动窗口的信息

## 语言风格与语法

Hyprland 使用 [Lua](https://lua.org/) 编写配置文件。Lua 是一种易用且高效的脚本语言，广泛用于各类软件。

<a id="using-multiple-configuration-files"></a>

#### 使用多个配置文件

配置可以拆分到多个文件或模块中。要加载其他模块，请使用 Lua 的 [`require`](#require) 函数。你可以使用绝对路径、相对于 `hyprland.lua` 所在目录的路径，或系统级安装的模块名称来指定模块。

在 `require` 中，`.` 和 `/` 都可用作目录分隔符，但通过相对路径导入时应优先使用 `.`。

可以使用通配符 `*` 从某个目录加载多个文件，或在指定路径下的所有目录中搜索。使用通配符时，路径必须采用 UNIX 格式。


<details><summary>示例</summary>


```lua
-- 指向 $XDG_CONFIG_HOME/hypr/awesomeconf/animation.lua
require("awesomeconf.animation")
-- 指向 $XDG_CONFIG_HOME/hypr/awesomeconf/keybinds.lua
require("awesomeconf/keybinds")

-- 会尝试加载目录中的所有文件
require("./lua/*")
-- 会尝试加载各子目录中的 "loadme.lua" 文件
require("./lua/*/loadme")

-- 会从 /usr/share/among 加载 "us.lua"
require("/usr/share/among/us")
```



</details>

<a id="require"></a>

#### 使用 require 加载文件

使用 `require` 可将其他文件加载到配置中。**强烈**推荐这种做法，因为 Hyprland 专门为每次 `require` 调用提供了独立的 Lua“作用域”，所以通过 `require` 加载的某个文件即使出错，也 _不会_ 中断其他文件的执行。

请注意，许多错误都会导致当前 Lua 文件停止执行。有关出错时的具体行为，详见[下文](#error-behavior)。

`require` 的保护机制不适用于模块加载过程。如果尝试加载不存在的模块，`require` 会在调用它的文件中抛出错误。也就是说，在 Hyprland 主配置文件中调用 `require("nonexistent")`，_会导致主配置文件停止执行_。

如果想避免这类错误影响配置运行，甚至希望在运行时检测并处理它们，可以使用 Lua 的 `pcall()` 函数，例如：

```lua
local status, value = pcall(require, "maybe-nonexistent")
if status then
  print("Successfully loaded module, it returned:", value)
else
  print("Failed to load module, its error message was:", value)
end
```

<a id="ignoring-requires-protection"></a>

##### 绕过 `require` 的保护机制

要绕过作用域隔离，可以通过 `__require` 使用 Lua 原生的 `require`。你可以直接调用 `__require`，也可以设置 `require = __require`，将原生实现恢复为默认实现。如果你加载的第三方模块因 Hyprland 的错误保护机制而无法正常工作，后一种做法可能会有所帮助。

<a id="editor-autocompletion"></a>

#### 编辑器自动补全

预先生成的 Lua 存根文件位于 `/usr/share/hypr/stubs/` 目录中（在 NixOS 系统上位于 `/run/current-system/sw/share/hypr/stubs/`）。在 LSP 配置中将该目录加入 Lua 工作区，即可启用自动补全。

如果不想配置 LSP，也可以直接阅读这些存根文件。





<details><summary>通用</summary>


在仓库根目录中添加 `.luarc.json` 文件，然后执行以下步骤：

```json
{
  "workspace": {
    "library": [
      "/usr/share/hypr/stubs"
    ]
  }
}
```



</details>


<details><summary>VS Code</summary>


在 `.vscode/` 目录中创建 `settings.json` 文件（如果目录不存在，请先创建目录），然后执行以下步骤：

```json
{
  "Lua.workspace.library": [
    "/usr/share/hypr/stubs"
  ]
}
```



</details>




<a id="error-behavior"></a>

#### 出错时的行为

Hyprland 会尽可能减小错误的影响。不过，有些错误无法妥善处理：
- 如果出现基本的 Lua 语法错误，Hyprland 会拒绝重新加载配置，并弹出错误提示。
- 如果在运行时出现 Lua 语法错误（例如将 `nil` 当作函数调用），Hyprland 会中止当前 Lua 文件的执行，并弹出错误提示。
- 如果在运行时出现 Hyprland 类型错误（例如向 `hl.*` 传入字符串，而对应参数要求浮点数），Hyprland 会弹出错误提示，并继续执行。
- 异步执行期间（例如执行按键绑定对应的函数时）若发生运行时错误，Hyprland 会弹出通知，说明错误详情。

如果发生错误时还没有注册任何按键绑定，Hyprland 会注册几个应急按键绑定：`SUPER + Q` 打开终端，`SUPER + R` 打开 hyprlauncher，`SUPER + M` 退出 Hyprland。错误弹窗中会列出这些按键绑定。

<a id="infinite-loops-reentrant-events"></a>

#### 无限循环与可重入事件

Hyprland 设有保护机制，防止无限运行的脚本导致会话崩溃。一旦脚本运行超时或达到指定上限，Hyprland 就会终止脚本。

<a id="standard-library"></a>

#### 标准库

默认会加载 Lua 标准库。Lua 脚本**可以在你的计算机上执行任意代码**，请确保配置来源可信。

<a id="testing-with-repl"></a>

#### 使用 REPL 测试

借助 [hyprctl 内置的 Lua REPL](advanced-configuration/using-hyprctl.md#repl)，你可以轻松探索 API 和 Lua 状态。
