    议题指南

    由于收到大量质量不高或难以理解的议题，我们希望大家先以讨论的形式报告疑似缺陷或提出功能请求。 待项目成员确认问题与项目相关，且收集到足够信息后，我们会将讨论转为议题。

    [!NOTE] 为什么要这样做？ 我们都是志愿者，利用业余时间维护项目。 出于对大家的尊重，请在提交议题 或 发起讨论前 完整阅读 本文。 你花几分钟阅读，就能为开发者节省更多时间，让我们更快地修复缺陷、推出新功能。

    谢谢！

    议题指南 #

    如果你遇到缺陷，或发现缺少某项功能，请不要直接创建议题。 请先发起讨论。

    发起讨论前 #

    请仔细搜索已有的讨论和议题。 你遇到的缺陷或想要的功能很可能已经有人提出，而且讨论或议题仍然开放。直接投赞成票即可，这样既省去你重新撰写的时间，也省去我们关闭重复条目并引导你前往原帖的时间。

    讨论的处理流程 #

    讨论由用户发起。

    对于缺陷报告：

    • 如果问题已解决、由用户操作失误引起，或与 Hyprland 无关，讨论就会关闭。
    • 如果问题涉及 Hyprland，但还无法明确确认是 Hyprland 所致，或问题无法复现，就会保留为讨论，直到情况发生变化。
    • 如果问题可以复现，Hyprland 项目成员会将讨论转为议题，具体做法是新建议题，写明关键信息，并附上原讨论的链接。

    说明

    如需获取与缺陷相关的日志，请参阅崩溃与缺陷。

    对于功能请求：

    • 如果请求的功能已经可以实现（通过脚本、现有功能或官方工具），或者请求无效或不适用，讨论就会关闭。
    • 如果请求的功能 尚无法 实现，就会保留为讨论。
    • 如果请求的功能 尚无法 实现，而且讨论获得了足够关注，项目成员可能会将其转为议题，具体做法是新建议题，写明关键信息，并附上原讨论的链接。

    请留意，我们都是志愿者，而且人手有限，因此有些议题可能暂时无人处理。

    如何让自己发起或关心的讨论获得关注 #

    请避免发表“什么时候修？”之类的评论。 请给讨论投赞成票；如果已有对应议题，也可以给议题投赞成票。

    如果讨论已获得至少 5 票赞成，但仍未转为议题，你可以在讨论中 @ 一位项目成员 （联系 @vaxerski、@fufexan 或 @notashelf 最有可能得到回应）。

    请不要仅仅因为讨论沉寂或缺少关注就 @ 项目成员。 遇到这种情况，可以补充更多可能引发交流的相关信息，让讨论回到正轨，也可以把讨论告诉对此感兴趣的人，让他们有机会投赞成票。
